# Власний блокчейн з нуля

Навчальна реалізація невеликої криптовалюти "з нуля": гаманці, підписані
транзакції, мемпул, блоки з деревом Меркла, Proof of Work з автоматичним
коригуванням складності, мережа з кількох вузлів, що домовляється про
єдину історію транзакцій, та консольний клієнт.

Виконано в межах практичного заняття №1 "Технологія блокчейн та машинне
навчання" (НУРЕ).

## Що написано власноруч, а що взято з бібліотек

Згідно з умовою завдання, готові бібліотеки використані лише для
допоміжних речей:

- `hashlib` (стандартна бібліотека Python) — SHA-256;
- `ecdsa` — підпис/перевірка ECDSA на кривій secp256k1 (сама математика
  еліптичних кривих не переписувалась, як і не вимагалось умовою);
- `flask` — HTTP-сервер вузла;
- `requests` — HTTP-клієнт для спілкування вузлів між собою;
- `matplotlib` — побудова графіка експерименту;
- `pytest` — запуск тестів.

Усе інше — транзакції та їх серіалізація, мемпул, блок, дерево Меркла,
Proof of Work, коригування складності, ланцюг і його повна перевірка,
консенсус між вузлами — написано власноруч у пакеті `blockchain/`.

## Структура проєкту

```
blockchain/
  crypto_utils.py   — SHA-256, канонічна серіалізація, ключі ECDSA
  wallet.py         — гаманець (генерація/збереження ключів, адреса)
  transaction.py    — транзакція, детермінована серіалізація, підпис
  mempool.py        — черга непідтверджених транзакцій (4 перевірки)
  merkle.py         — дерево Меркла + доказ Меркла (SPV)
  block.py          — заголовок блоку, блок, генезис
  mining.py         — Proof of Work (підбір nonce)
  difficulty.py     — автоматичне коригування складності
  chain.py          — ланцюг, баланси, повна перевірка, збереження/завантаження
  node.py           — HTTP-вузол (Flask) + консенсус між вузлами
cli.py              — консольний клієнт керування вузлом
tests/              — 36 автоматичних тестів (pytest)
attacks/
  demo_attacks.py   — демонстрація 5 атак і реакції системи
  demo_fork.py      — демонстрація штучного розгалуження мережі
experiment/
  measure_difficulty.py — вимірювання часу майнінгу для 4 рівнів складності (10 запусків кожен)
  plot_results.py       — побудова графіка (логарифмічна вісь часу)
  results.json           — отримані виміри
  difficulty_experiment.png — готовий графік
```

## Встановлення

Потрібен Python 3.9+.

```bash
pip install -r requirements.txt
```

## Запуск мережі з трьох вузлів (одна-дві команди)

Найпростіше — окремим терміналом на кожен вузол:

```bash
python3 -m blockchain.node --port 5001 --data chain_5001.json
python3 -m blockchain.node --port 5002 --data chain_5002.json
python3 -m blockchain.node --port 5003 --data chain_5003.json
```

Або одним рядком (Linux/macOS, запуск у фоні):

```bash
for p in 5001 5002 5003; do python3 -m blockchain.node --port $p --data chain_$p.json & done
```

Після запуску познайомте вузли одне з одним:

```bash
curl -X POST http://localhost:5001/nodes/register -H "Content-Type: application/json" \
     -d '{"peers":["http://localhost:5002","http://localhost:5003"]}'
curl -X POST http://localhost:5002/nodes/register -H "Content-Type: application/json" \
     -d '{"peers":["http://localhost:5001","http://localhost:5003"]}'
curl -X POST http://localhost:5003/nodes/register -H "Content-Type: application/json" \
     -d '{"peers":["http://localhost:5001","http://localhost:5002"]}'
```

## Консольний клієнт (`cli.py`)

```bash
# створити гаманець
python3 cli.py wallet-new --out alice.json

# намайнити блок (винагорода піде на адресу гаманця)
python3 cli.py --node http://localhost:5001 mine --miner <адреса>

# надіслати транзакцію
python3 cli.py --node http://localhost:5001 send --wallet alice.json --to <адреса> --amount 10 --fee 0.1

# показати ланцюг / баланс / перевірити ланцюг
python3 cli.py --node http://localhost:5001 chain
python3 cli.py --node http://localhost:5001 balance <адреса>
python3 cli.py --node http://localhost:5001 validate

# сусіди і синхронізація
python3 cli.py --node http://localhost:5001 add-peer http://localhost:5002
python3 cli.py --node http://localhost:5001 peers
python3 cli.py --node http://localhost:5001 sync
```

Ці ж дії доступні напряму через REST API вузла (див. `blockchain/node.py`
— `create_app()` — повний список ендпоінтів).

## Тести

```bash
python3 -m pytest tests/ -v
```

36 тестів: транзакції та підписи, дерево Меркла (парна/непарна кількість,
доказ Меркла), мемпул (усі чотири перевірки), блок і PoW, повна перевірка
ланцюга, усі п'ять атак, збереження/завантаження, коригування складності.

## Демонстрація атак

```bash
python3 -m attacks.demo_attacks
```

Друкує в консоль послідовно всі п'ять атак із методички та пояснення,
чому кожна з них відхиляється.

## Демонстрація розгалуження мережі

Спочатку підняти три вузли (див. вище), познайомити лише вузли A і B
(вузол C свідомо НЕ реєструємо, щоб зімітувати розрив мережі), після чого:

```bash
python3 attacks/demo_fork.py
```

Скрипт майнить конкурентні блоки на різних вузлах, показує розгалуження
за сумарною роботою, а потім "підключає" відрізаний вузол назад і
викликає `/nodes/resolve` — вузол переходить на важчий ланцюг, а
транзакція з програного блоку повертається в мемпул.

## Експеримент зі складністю

```bash
python3 -m experiment.measure_difficulty   # вимірювання (results.json)
python3 -m experiment.plot_results         # графік (difficulty_experiment.png)
```

У поставці репозиторію складність для експерименту обрана як 2–5 нулів
(а не, скажімо, 4–7), щоб укластися у розумний час у навчальному
середовищі; принцип і форма кривої (експоненційне зростання, майже
пряма лінія на логарифмічній шкалі часу) від цього не змінюються.

## Приватні ключі

Жоден файл гаманця з приватним ключем не входить до репозиторію
(`*.json` гаманців потрапляють у `.gitignore`). Файли ланцюга
(`chain_*.json`) також не комітяться — кожен вузол відновлює або
створює їх самостійно під час запуску.
